# Domain Graph Analyzer — руководство пользователя

Инструмент для анализа доменных схем: строит граф связей между доменами, ищет проблемы, помогает планировать изменения. Работает с локальной директорией или скачивает схемы с сервера.

## Быстрый старт

**Локальный режим** — схемы уже на диске:

```bash
node graph-analyzer.js ./domains 3000
```

**Удалённый режим** — скачать с сервера:

```bash
node graph-analyzer.js --server https://your.site.url --login admin --password "qwerty"
```

Откройте [http://localhost:3000](http://localhost:3000).

---

## Режимы работы

### Локальный

Читает все `.ro` файлы в директории (рекурсивно), парсит YAML, строит граф.

```bash
node graph-analyzer.js <directory> [port]
```

### Удалённый

Логинится на сервер, скачивает структуру папок и все ENABLED-домены, сохраняет в кэш, потом работает с ним как с обычной директорией.

```bash
node graph-analyzer.js --server <url> --login <user> --password <pass> [options]
```

**Что происходит:**
1. Логин → accessToken
2. Загрузка структуры папок
3. Загрузка списка ENABLED-доменов
4. Скачивание `sourceCode` каждого домена с сохранением структуры папок
5. Запуск веб-сервера

**Кейс**: перед ревью архитектуры — обновить кэш и проверить актуальные связи.

```bash
node graph-analyzer.js --server https://your.site.url --login admin --password "qwerty" --refresh
```

## Кэш

**Расположение**: `.cache/domains/<hostname>__<hash>/` рядом со скриптом.

**Структура:**

```
.cache/domains/your.site.url__11dbb506/
├── .complete                # маркер успешной загрузки
├── _index.json              # метаданные: папки, домены, время
├── _errors.json             # ошибки загрузки (если есть)
├── _validation.json         # последняя валидация
├── sgrc/
│   ├── audit/domains/
│   │   └── sgrc.evo.compliance.audit.ro
│   └── safeguards/domains/
│       └── sgrc.evo.safeguards.ro
└── isassets/domains/
    └── it.assets.rvision.ru.ro
```

**Стратегии:**

- Есть кэш → используется, запросов к серверу нет
- Есть кэш + `--refresh` → перезакачивает
- `--reset-cache` → удаляет и загружает заново
- Нет кэша → загружает

Когда страница открыта из кэша — в правом верхнем углу жёлтый тост с датой кэша и командой для обновления.

## Полоса активных режимов

Появляется под тулбаром, если включён хотя бы один режим. Каждый чип — с крестиком для сброса.

Примеры чипов:
- `🔁 Циклы (3) ✕` — включена подсветка циклов
- `🎯 Фокус N=2 ✕` — focus mode
- `🛤️ Путь ✕` — построенный путь
- `👁 Скрыто: 5` — скрытые узлы
- `❌ Только невалидные` — фильтр невалидных
- `★ Только избранные` — фильтр избранных
- `🗂 Агрегация по семействам` — режим семейств
- `📦 Уровни установки` — раскраска по уровням топосорта
- `⇄ Diff +2/−1` — активный diff
- `⛔ Нарушения: 5` — активные правила
- `🚫 Тултипы выключены` — тултипы скрыты

**Кейс**: открыть 4 разных режима и потом сбросить их одним кликом, не открывая меню.

## Граф

### Типы узлов

| Иконка | Тип | Значение |
|--------|-----|----------|
| 🟢 ● | Domain | Корректный домен |
| 🟠 ▲ | Missing | Ссылка на несуществующий домен |
| 🔴 ✕ | Broken | Файл, который не удалось распарсить |

### Типы связей

| Цвет | Тип |
|------|-----|
| 🟣 Сине-фиолетовый пунктир | Linkage (явная связь из `linkages[]`) |
| 🟢 Зелёный | FQID (неявная ссылка через `domain/entity`) |
| 🟡 Жёлтый | Выделенная связь (клик) |
| 🟠 Оранжевый | Цикл |
| 🔴 Красный | Нарушение правил |

### Дополнительные индикаторы

- **★** слева от ID — узел в закладках
- **L1, L2** в правом верхнем углу — уровень из топосорта
- **Цифра** в правом верхнем углу — health score (0–100)

## Фильтры

Меню **⚙️ Фильтры**:

### Типы узлов
- Domain, Missing, Broken — вкл/выкл

### Типы связей
- Linkage, FQID — вкл/выкл

### Namespace

Поле с масками. Синтаксис:

| Паттерн | Действие |
|---------|----------|
| `sgrc.evo.*` | Все домены внутри `sgrc.evo` |
| `users.rvision.ru` | Только этот домен |
| `sgrc.*, users.*` | Несколько масок (`,`, `;` или пробел) |
| `!test.*` | Исключить |
| `sgrc.*, !sgrc.legacy.*` | Включить, кроме legacy |

### Дополнительно
- ☐ **Только избранные (★)** — показать только закладки
- ☐ **Только невалидные (❌)** — только те, что не прошли массовую валидацию
- ☐ **Только изолированные (◯)** — без связей
- ☐ **Скрывать тултипы** — отключить всплывающие подсказки

**Кейс**: посмотреть только `sgrc.evo.*`, исключив legacy:

```
sgrc.evo.*, !sgrc.evo.legacy.*
```

**Кейс**: разобраться, что вокруг `sgrc.evo.safeguards` — кто от него зависит и от кого зависит он.

## Порядок установки (топосорт)

Меню **📊 Анализ** → «📦 Порядок установки».

### Зачем

Понять, в каком порядке устанавливать домены, чтобы не было проблем с зависимостями. Домены без зависимостей можно ставить параллельно.

### Как работает

1. **Область** — все / видимые / избранные
2. **Учитывать зависимости** — FQID-ссылки, linkage-связи
3. **Missing-домены считать установленными** — пропускать их из порядка
4. **Исключить домены по маске** — например `*.settings.*` (уже установлены)
5. **Автоматически разрывать циклы** — если включено, домены с циклом размещаются с пометкой

На выходе — **уровни**, которые можно ставить параллельно. Внутри уровня — всё одновременно.

### Результат

```
Уровень 1 (4 домена)  →  ставим параллельно
  sgrc.evo.compliance.audit.settings
  sgrc.evo.risk.settings
  users.rvision.ru
  it.assets.rvision.ru

Уровень 2 (5 доменов)  →  параллельно
  sgrc.evo.safeguards
  sgrc.evo.compliance.audit
  ...
```

Для каждого домена можно раскрыть его **прямые зависимости** — увидеть, что именно он требует.

### Метрики

- **Всего доменов** — сколько в области
- **Уровней** — минимальное число последовательных шагов
- **Критический путь** — длина самого длинного пути зависимостей
- **Разорвано** — сколько циклов пришлось разорвать (если авторасрыв)

### Авторасрыв циклов

Если включена галочка, при застревании на цикле выбирается **наименее зависимый** узел, его внутренние связи отрезаются, он размещается в текущем уровне. Узел получает бейдж `⚠️ цикл разорван`, вверху — блок «🔗 Циклы разорваны автоматически (N)».

### Экспорт

- **💾 JSON** — полная структура с уровнями и разрывами
- **📝 Markdown** — отчёт для Confluence
- **📋 Копировать** — простая текстовая выжимка
- **🎨 На графе** — раскраска узлов по уровням (бейджи L1, L2...)

**Кейс**: планировать деплой — видишь, что первый уровень параллелится, второй идёт после него, всего 5 шагов.

## Массовая валидация

Меню **💾 Данные** → «🔍 Массовая валидация доменов». Доступно только в режиме `--server`.

### Зачем

Прогнать все домены через API `checkRobject`, найти те, что содержат ошибки валидации. Результаты — с диагностикой от сервера.

### Как работает

1. Выбираете область: все / видимые / избранные
2. Запуск — параллельно, лимит 3 запроса
3. Прогресс-бар и лог в реальном времени

### Логи

- ✅ Валиден
- ❌ Невалиден — с раскрывающейся диагностикой (message, severity, labels, span)
- ⚠️ Ошибка запроса (сеть, 401)

Клик по имени домена — переход к узлу на графе.

### Фильтры логов

- Только проблемные (по умолчанию)
- Все
- ❌ Невалидные
- ⚠️ Ошибки
- ✅ Валидные

### Результаты

- Невалидные узлы получают **красную обводку** на графе
- Кнопка `❌` в полосе активных режимов — фильтр «только невалидные»
- Результаты сохраняются в `.cache/.../_validation.json` и подгружаются при F5

### Экспорт

- **💾 JSON** — полный отчёт
- **📝 Markdown** — отчёт с диагностикой по каждому невалидному

### Обработка 401

Если accessToken истёк — сервер автоматически перелогинивается один раз и повторяет запрос. При повторном 401 — прерывает.

**Кейс**: перед релизом — прогнать все домены, найти 9 невалидных, посмотреть диагностику, поправить.

## Правила зависимостей

Меню **📊 Анализ** → «⛔ Правила зависимостей».

### Зачем

Ограничить связи между неймспейсами по архитектурным правилам.

### Формат правила

```
from: ui.*       # откуда
to:   db.*       # куда
action: forbid   # forbid (⛔ красный) или warn (⚠️ жёлтый)
message: 'UI не должен ходить в БД напрямую'
```

Маски в `from` и `to` работают так же, как в фильтре namespace.

### Как работает

- Правила хранятся в localStorage
- Все рёбра проверяются на соответствие
- Нарушения подсвечиваются: ⛔ красным (forbid), ⚠️ жёлтым (warn)
- В полосе активных режимов — бейдж `⛔ Нарушения: N`

### Опции

- ☑ **Подсвечивать нарушения** — включить/выключить визуализацию
- ☑ **Показать только нарушения** — фильтр рёбер

### Примеры правил

**Слоистая архитектура:**
```
ui.* → db.* (forbid)
infra.* → *.domain.* (forbid)
```

**Монорепо изоляция:**
```
product-a.* → product-b.* (forbid)
```

**Запрет новых связей с legacy:**
```
* → legacy.* (warn)
```

**Кейс**: ввели архитектурное правило «UI не общается с БД напрямую». Добавили правило, сразу видно все нарушения в графе.

## Вид и раскраска

Меню **🎨 Вид**:

### Раскладка
- **LR** — горизонтальная (по умолчанию, для dagre)
- **TB** — вертикальная
- **Force-directed** — физическая симуляция, для сложных графов
- **Circular** — по кругу, для обзора

### Heatmap

Раскраска узлов по метрике:
- **Health score** — от красного (0) до зелёного (100)
- **Количество связей** — серый → синий → зелёный
- **Entities** — серый → фиолетовый → розовый
- **Исходящие FQID** — серый → cyan

Внизу графа — легенда с min/max значениями.

**Кейс**: посмотреть по heatmap, кто в доменной системе «главный узел» (много связей), а кто — проблемный (низкий health).

### Компактный режим

Узлы в виде маленьких кружков с первой буквой ID. Для больших графов.

### Группировка в рамки

Визуальные прямоугольники вокруг неймспейсов (первые 2 сегмента id). Не схлопывает — просто выделяет.

### Объединять A↔B

Двунаправленные связи одним ребром с двумя стрелками.

### Подписи связей

Показывать подписи постоянно (иначе — только на hover).

### Тема

Тёмная / светлая.

**Кейс**: для презентации — светлая тема + группировка в рамки + подписи связей.

## Работа с узлами и связями

### Клик по узлу

Открывается боковая панель:
- Вкладка «📋 Детали»: id, name, version, description, tags, health, FQID-ссылки, входящие/исходящие связи
- Вкладка «📄 Файл»: содержимое `.ro` файла в Monaco

### Клик по связи

Открывается панель с деталями связи:
- id, kind (linkage/fqid), type
- источник → цель
- FQID-ссылки с путями
- кнопки «🎯 К источнику», «🎯 К цели»

### Двойной клик по узлу

Focus mode — только его окружение.

### Ctrl/Cmd + клик

Добавить в выделение для построения пути.

### Правая кнопка

Контекстное меню:
- 🎯 **Фокус (N шагов)**
- 📊 **Что зависит от него** — расширенный фокус
- 🛤️ **Путь от...** — выбрать начальный узел, потом целевой
- ↪️ **Путь до...** — наоборот
- 📂 **Открыть файл**

### Path finder

Два способа:
1. Ctrl+клик на двух узлах → «🛤️ Найти путь» в полосе активных режимов
2. ПКМ → «Путь от» → клик по второму узлу

Путь подсвечивается жёлтым. Esc снимает.

**Кейс**: понять, как `sgrc.evo.audit` связан с `it.assets` — через какие домены идут зависимости.

### Закладки

ПКМ → «★ В закладки» или клавиша `B` при выделенном. Кнопка `★` в полосе активных режимов — показать только избранные.

**Кейс**: помечать домены, над которыми сейчас работаете. При следующем запуске они не потеряются (localStorage).

### Скрытие

ПКМ → «👁 Скрыть». Чип `👁 Скрыто: N` в полосе активных режимов, клик — вернуть все.

## Кейсы применения

### 1. Подготовка к релизу

**Задача**: убедиться, что все домены валидны и нет неожиданных связей.

1. `--refresh` — обновить кэш
2. `💾 Данные` → «Массовая валидация» → все домены
3. Смотрим `❌ Невалидные` — их N штук. Кликаем по каждому, читаем диагностику
4. Экспорт Markdown → приложить к тикету

### 2. Планирование деплоя

**Задача**: понять порядок установки доменов.

1. `📊 Анализ` → «📦 Порядок установки»
2. Область: все домены
3. Опции: учитывать FQID + linkage, missing считать установленными
4. Исключить `*.settings.*` (они уже стоят)
5. Построить → получить уровни
6. Экспорт в Markdown → отдать DevOps

### 3. Ревью архитектуры

**Задача**: проверить, что правила слоёв соблюдаются.

1. `📊 Анализ` → «⛔ Правила зависимостей»
2. Добавить: `ui.* → db.* forbid`, `infra.* → *.domain.* forbid`
3. Видеть нарушения в графе
4. Экспорт Markdown с нарушениями — обсудить с командой

### 4. Разбор инцидента

**Задача**: понять, что сломается при недоступности домена X.

1. Найти X через поиск
2. ПКМ → «📊 Что зависит от него» — расширенный фокус (3 шага)
3. Видим все домены, которые косвенно зависят
4. Понимаем масштаб

### 5. Поиск «узких мест»

**Задача**: найти домены с большим числом связей.

1. `🎨 Вид` → Heatmap → «Количество связей»
2. Самые горячие (красные/зелёные) — узкие места
3. Смотрим в панели деталей: сколько входящих, сколько исходящих
4. Решаем: разбить или оставить

### 6. Онбординг нового разработчика

**Задача**: показать архитектуру.

1. Открыть с `--server`, показать агрегацию по семействам — 5–7 групп вместо 50 доменов
2. Затем включить «Объединять A↔B» и «Подписи связей»
3. Дать походить по узлам через клики, открыть панель деталей

### 7. Diff между версиями

**Задача**: узнать, что изменилось после спринта.

1. Экспорт JSON в начале спринта
2. Экспорт JSON в конце
3. `💾 Данные` → «Загрузить снимок» → первый файл
4. Видим добавленные (зелёные) и удалённые (красные) связи

### 8. Проверка изоляции продукта

**Задача**: убедиться, что домены продукта не зависят от чужих.

1. Namespace-фильтр: `product-a.*`
2. Все связи на графе — только внутри продукта или на missing
3. Если есть связи с `product-b.*` — сразу видно

## Troubleshooting

### «EADDRINUSE: address already in use :::3000»

```bash
lsof -ti:3000 | xargs kill -9
```

Или используйте другой порт: `--port 4000`.

### «self-signed certificate»

По умолчанию отключено. Флаг `--secure` включает проверку.

### «Логин: accessToken отсутствует»

Проверьте логин/пароль. Если пароль был изменён — обновите в команде.

### Тултипы не появляются

Проверьте в `⚙️ Фильтры` — не стоит ли «Скрывать тултипы». Если стоит — снимите, чип `🚫` в полосе активных режимов исчезнет.

### Граф пустой после фильтров

Проверьте:
- Все типы узлов и связей в `⚙️ Фильтры` активны
- Поле namespace пустое
- Не включены фильтры «только избранные», «только изолированные», «только невалидные»

### Массовая валидация недоступна

Кнопка не появляется, если сервер запущен без `--server`. Валидация работает только в удалённом режиме.

### «YAML parse: unknown tag»

Если одиночный — пропускается. Если много — возможны проблемы в схемах на сервере.

### Пропала связь после обновления

Кэш устарел. `--refresh`.

### Обновление кэша вручную

```bash
# Из тоста — скопировать команду
# Или напрямую:
node graph-analyzer.js --server ... --login ... --password ... --refresh
```

### Кэш испорчен

```bash
node graph-analyzer.js --server ... --login ... --password ... --reset-cache
```

Или удалить папку:

```bash
rm -rf .cache/domains/your.site.url__*
```
